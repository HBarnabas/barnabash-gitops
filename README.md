# barnabash-gitops

GitOps source of truth for my PC k3s cluster, reconciled by [Flux](https://fluxcd.io).
The RPi5 bootstrap and infrastructure configuration is retained for possible
future use, but its app reconciler is removed. Workload manifests live in
`apps/base`; `apps/pc-k3s` defines the independent PC Flux reconciliations.

## Repository layout

```
clusters/pc-k3s/              # Flux entrypoints (bootstrap writes flux-system/)
  ├─ flux-system/             # generated by `flux bootstrap`
  ├─ infrastructure.yaml      # infra-controllers -> infra-configs
  └─ apps.yaml                # app Kustomization orchestrator
clusters/rpi5-k3s/            # retained bootstrap + infrastructure; no apps reconciler

apps/
  ├─ base/                    # shared manifests, grouped by app
  └─ pc-k3s/
      ├─ kustomization.yaml   # Flux Kustomizations for each app
      └─ *.yaml                # Flux Kustomizations for each app

infrastructure/
  ├─ controllers/base         # cert-manager, ingress-nginx, reloader, Helm sources
  ├─ controllers/pc-k3s       # k3s provides ServiceLB + local-path
  ├─ configs/base             # Let's Encrypt ClusterIssuers
  └─ configs/pc-k3s           # inherits base
```

Reconcile order: `infra-controllers` → `infra-configs` → the app Kustomizations.
Each app is reported independently in Flux. The media namespace intentionally
remains one reconciliation unit for now.

## App reconciliation units

| Flux Kustomization | Workload |
|--------------------|----------|
| `apps-ddns` | Dynamic DNS updater |
| `apps-headscale` | Headscale |
| `apps-immich` | Immich and its database |
| `apps-immich-backup` | Immich backup jobs; depends on `apps-immich` |
| `apps-media` | Media namespace (kept grouped for now) |
| `apps-minecraft` | Minecraft |
| `apps-pi-hole` | Pi-hole |
| `apps-sources` | Shared Helm and OCI sources |

## Prerequisites

Install locally: `flux`, `kubectl`, `kustomize`, `sops`, `age`.

## Bootstrap

1. Create a k3s cluster on the target machine and point
   `KUBECONFIG` at it.
2. **Before first bootstrap**, review the TODOs:
   - `.sops.yaml` — put your age **public** key.
   - `infrastructure/configs/base/cluster-issuers.yaml` — your email.
   - Mount the PC data disk at `/mnt/hdd` before workloads start, or update
     the shared PV host paths.
   - Each app's domain (`*.example.com`) and secrets.
3. Bootstrap the PC cluster:

   ```sh
   flux bootstrap github \
     --owner=<your-github-user> \
     --repository=barnabash-gitops \
     --branch=main \
     --path=clusters/pc-k3s \
     --personal
   ```

The retained RPi5 configuration can be bootstrapped later with
`--path=clusters/rpi5-k3s`; its app reconciler must be added back when the
cluster is ready to run workloads again.

4. Create the SOPS decryption key in-cluster so Flux can decrypt secrets:

   ```sh
   cat age.key | kubectl create secret generic sops-age \
     -n flux-system --from-file=age.agekey=/dev/stdin
   ```

## Secrets (SOPS + age)

Secrets are committed **encrypted** with SOPS. Files named `*.sops.yaml` are
encrypted (only `data`/`stringData` values). Workflow:

```sh
age-keygen -o age.key                      # once; keep age.key private (gitignored)
# put the public key in .sops.yaml
sops apps/base/immich/secret.sops.yaml     # edit -> saved encrypted
```

The shipped `*.sops.yaml` files are **plaintext templates** — fill them in and
run `sops --encrypt --in-place` on each before pushing.

## Validating changes locally

No cluster needed to catch structural errors:

```sh
kustomize build apps/pc-k3s
for app in ddns headscale immich immich-backup media pi-hole minecraft sources; do
  kustomize build "apps/base/$app"
done
kustomize build apps/base
kustomize build infrastructure/controllers/pc-k3s
kustomize build infrastructure/configs/pc-k3s
```

## Moving to per-app reconciliation

Flux tracks resources in each Kustomization's inventory. To avoid pruning
workloads while moving them from the old `apps` inventory to the new child
Kustomizations:

1. First change only `spec.prune` to `false` on the existing `apps`
   Kustomization in `clusters/pc-k3s/apps.yaml`. Reconcile that change and
   confirm it is applied with `flux export kustomization apps -n flux-system`.
2. Apply the per-app layout. Keep `apps` pruning disabled while its children
   adopt the existing resources. Check `flux get kustomizations -n flux-system`
   and use `flux tree kustomization apps -n flux-system` to confirm each
   retained app's objects are now under its child Kustomization. The retired
   WireGuard objects may remain in the old inventory for cleanup.
3. Re-enable `spec.prune: true` on the parent `apps` Kustomization and
   reconcile. This restores cleanup for removed child Kustomizations; resources
   not adopted by a child are pruned. That intentionally removes the retired
   WireGuard namespace and its PVC.

The workload manifests keep their existing Kubernetes names and namespaces, so
the new Kustomizations apply those objects in place rather than replacing them.

## Version pinning

Verify the latest stable versions on Artifact Hub before your first bootstrap.
